# Sinh ID và identity

## 1. Problem — vì sao cần khái niệm này?
Nhiều client cùng thêm dữ liệu cần ID duy nhất. Lấy MAX(id)+1 ở ứng dụng sẽ có race condition.

## 2. Mental model
IDENTITY dùng cơ chế identity của database khi INSERT. SEQUENCE lấy số từ database sequence; Hibernate có thể cấp phát theo nhóm tùy mapping. ID không phải số thứ tự liên tục của danh sách.

## 3. Ví dụ nhỏ
@GeneratedValue(strategy = GenerationType.IDENTITY) ↔ BIGINT GENERATED BY DEFAULT AS IDENTITY trong schema lab.

Đọc [demo](demo/README.md); ghi dự đoán SQL trước khi chạy.

## 4. Liên hệ kiến thức đã học
JDBC: INSERT ... RETURNING id; SQL: primary key/sequence. Java Core: Long nullable biểu diễn entity mới chưa có ID. HTTP POST có thể trả id mới, client không tự chọn id từ số hàng.

## 5. Những lỗi thường gặp
Dùng MAX(id)+1; coi id liên tục là yêu cầu transaction; gán id bằng tay cho entity mới với chiến lược generated; nhầm save với commit.

## 6. Câu hỏi tự kiểm tra
Rollback rồi id có được tái sử dụng không? Vì sao IDENTITY có thể khiến INSERT xuất hiện trước commit?
